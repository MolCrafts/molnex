# Re-check F29 on every eager public calc_energy; keep energy() compile-clean

## Summary

Class-I `Potentials` must stop treating object identity of a batch — or a previous `warmup` — as proof that the current geometry is valid. Every eager public `bind_topology` / `calc_energy` (and `warmup`, which binds) re-runs the unwrapped-bond (F29) check on the positions and cell it is handed, so a reused TensorDict whose coordinates were rewritten, a fresh batch of the same topology shape, a batch evaluated after `warmup` on a different or mutated frame, and `torch.compile(calc_energy)` on an unvouched TensorFrame are all checked again: a folded molecule is refused instead of returning a finite, differentiable, wrong bonded energy. `energy()` is the `Derivative` seam and does **not** run that host check: it calls a private `_sum_energy` (the `term_energies` loop plus the mlip `call_energy` branch) and writes `graphs.energy`, which is the kernel compiled MD captures. The typed-view memo `_frame_view` stays: compiled MD still evaluates `op(work)` on the caller’s TensorDict, and that wrap identity is what keeps `as_tensor_frame` out of the CUDA-graph region. Verlet-skin neighbour lists and `CellBound.bind_cell` stay the runtime validity owners they already are. This spec does not retune `Compiler` / `Derivative`, edit `molix.md.driver`, retire `ForceAwareModel`, or add a dataset cache.

## Domain basis

This is not a new potential. Geometry validity is a physical precondition of the already-assembled Class-I energy, not a disposable index.

Bonded terms price the plain displacement \(r_{ij}=\lVert\mathbf{r}_j-\mathbf{r}_i\rVert\) (Å). Pair terms price the minimum-image separation from the molix-placed list (`edges.pair_diff`, `edges.shifts`). Wrapping a periodic molecule into the cell — the normal state of a trajectory read back from disk — leaves pair energies exact and stretches every bond, angle and torsion across the box. Finding **F29** (`.claude/notes/composable-potentials.md`): that number is finite, differentiable and wrong. The recorded F29 contract is one host sync (`int(argmax)` / `float`) at bind / public scoring, **nothing on the force path**. The edge convention is the other half of the same precondition: `pair_index[:,0]` is source, `pair_diff = pos[target]-pos[source]`, and `Potentials` prices the `source < target` half.

Under lattice vectors \(\mathbf{a}_1,\mathbf{a}_2,\mathbf{a}_3\) (rows of `graphs.cell`, Å) with volume \(V=\lvert\det(\mathrm{cell})\rvert\) (Å³), the minimum perpendicular width is

\[
w_{\min}=V\big/\max\lvert\mathbf{a}_i\times\mathbf{a}_j\rvert
\]

(Å). A bond is refused when its plain length exceeds \(w_{\min}/2\). For the in-tree cube of edge \(L=10\) Å that is \(5\) Å; atoms at \(x=(1,9)\) Å span \(8\) Å and must raise; the unwrapped copy \(x=(9,11)\) Å is a \(2\) Å bond and prices at

\[
E=\tfrac12 k(r-r_0)^2=\tfrac12\cdot 100\cdot(2-1)^2=50\ \mathrm{kcal/mol}
\]

with \(k=100\) kcal mol⁻¹ Å⁻² and \(r_0=1\) Å (`units="real"`). A sheared cell with the same edge lengths and \(w_{\min}=6\) Å refuses a \(4\) Å bond (limit \(3\) Å).

Object identity of a Python container is not a physical invariant: the same `id(batch)` can hold a whole molecule and then a folded one. Verlet-list completeness is a different, explicit contract — a list built at \(r_{\mathrm{build}}=r_{\mathrm{cut}}+s\) stays complete while \(\max_i\lVert\mathbf{x}_i(t)-\mathbf{x}_i(t_0)\rVert\le s/2\) (Verlet, *Phys. Rev.* **159**, 98 (1967), https://doi.org/10.1103/PhysRev.159.98) — and already lives on `molix.md.neighbors.NeighborList`, which this spec reuses and must not edit. Coordinate wrapping under PBC is the textbook source of F29 (Allen & Tildesley, *Computer Simulation of Liquids*, 2nd ed., Oxford, 2017, https://doi.org/10.1093/oso/9780198803195.001.0001). Runtime geometry binding is concern (5) of `.claude/notes/cache-layers.md`: host validation **before** the compiled region, never inside it.

## Design

**What exists today** (confirmed in `src/molpot/forcefield/potentials.py`; do not invent deletions of symbols that are already gone):

- `Potentials._checked_geometry: tuple[weakref.ref, tuple[int, ...]] | None` — F29 voucher keyed on `checked[0]() is frame`. A hit returns the cached topology fingerprint and **skips** `_check_bonds_unwrapped`. Positions are deliberately not part of the key. This is the F29 hole: a caller that writes wrapped positions or a new cell into the **same** TensorDict is not re-checked. `test_a_second_frame_of_the_same_shape_is_checked_afresh` only covers a *new* object.
- `Potentials._frame_view: tuple[weakref.ref, TensorFrame] | None` — wrap keyed on `cached[0]() is system`. This is **not** an F29 validity voucher. Compiled MD’s `_TensorDictForce.__call__` evaluates `op(work)` (`src/molix/md/driver.py` after `bind_work`), and `work` is the caller’s TensorDict, not the `TensorFrame` already built once as `self._frame` in `bind_work`. Polar’s measured seam is a dynamo break at `TypedTensorDict.__setattr__` on a fresh wrap; `_frame_view` is why a reused `work` object is wrap-clean after the eager prologue (1 graph / 0 wrap-breaks). NeighborList skin and `CellBound.bind_cell` do not replace it.
- `calc_energy` additionally skips `_check_geometry` when `self._warm` or `torch.compiler.is_compiling()` (`potentials.py:1200`). `warmup` sets `_warm=True` after binding **that** batch, so every later eager batch — including a wrapped one of the same shape — is unchecked. The `is_compiling()` branch at the `calc_energy` call site is the hatch `_check_geometry`’s docstring already forbids inside the check: a TensorFrame (or a TensorDict whose wrap already hit `_frame_view`) has no wrap break, so the skip traces F29 out of the graph and a folded molecule compiled on first contact returns a finite, differentiable, wrong bonded energy.
- `energy()` (`potentials.py:548-626`) currently calls `calc_energy` (line 617) then writes `ENERGY_KEY`. MD compiles that op (`driver.py:198-202`, `op(work)` at 395) after one eager eval. Today the second call is a memo / `_warm` / `is_compiling()` hit, so `Compiler(cuda_graphs=True)` `fullgraph=True` can capture. After deleting the memo **without** taking F29 off `energy()`, every bonded Class-I step re-enters `_check_bonds_unwrapped` (`int(argmax)` / `float` host sync) and CUDA-graph MD fails to compile. That is the previous draft’s 🚨, closed by the split below — **not** by skipping F29 inside the kernel.

This slug implements cache-layers concern (5) for `molpot.forcefield.potentials` only, with the two memos split and with F29 moved **off** the compiled kernel rather than skipped inside it. It does not depend on cache-layers-03-refs (element `c[Z]` is a different owner).

### Reuse decision

Geometry / neighbor validity (this slug):

- reuse `molix.md.neighbors.NeighborList` — Verlet skin, half-skin completeness, explicit rebuild / `ndanger`; not a dataset cache; **do not modify**.
- reuse `molix.neighbor.NeighborList` — pipeline cutoff graph that `Potentials._placed_pairs` already consumes; **do not modify**.
- reuse `molix.schema.CellBound.bind_cell` — and the existing `Potentials.bind_cell` delegation; cell-dependent inverses / k-grids are explicit runtime state; **do not modify** `molix.schema.CellBound`.
- reuse `molix.data.as_tensor_frame` / `TensorFrame` — zero-copy typed view, not a cache owner; `_frame` still memoizes the wrap on TensorDict identity (`_frame_view`).
- reuse `Potentials._frame_view` — wrap identity for compiled MD `op(work)`; **keep**; do not treat it as an F29 voucher.
- reuse `Potentials._check_bonds_unwrapped`, `bind_topology`, `_bound_topology`, `_scaled_pairs` — F29 physics and exclusion-table staleness; generalize nothing; do not reimplement a second unwrapped-bond check. Lazy `_scaled_pairs` → `bind_topology` F29 on first unbound pair-field `energy()` is this reuse, not a new voucher.
- new — none. The F29 object-identity memo is deleted, not replaced with another geometry cache. Private `Potentials._sum_energy` is extracted because `calc_energy` and `energy()` are the second use of the same loop + mlip branch, not a new type and not `MacePotential._sum_energy` (per-atom scatter × `atoms.mask`).
