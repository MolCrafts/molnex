## What this repo is

MolNex is a dict-first molecular ML framework for unified modeling of
molecular potentials and properties with physics-aware ML. Four packages:
molix (training), molrep (representation), molpot (potentials), molzoo
(encoder recipes). Python + PyTorch, with optional C++/CUDA engine
interfaces under `interface/`.

## Design preferences (default)

**Default for all MolCrafts projects.** Apply unless the operator
**explicitly** requires a functional (or other) style for a named
subsystem — then capture the exception with `/mol:note` and scope it.
Do **not** invent a functional style on your own.

### Iron law — no silent debt (all projects)

Discover anti-pattern / failing test / broken invariant / clear bug
in the surface you touch or depend on → **prioritize or hard-stop**:

1. **Do not ignore** ("pre-existing, leave it"), skip-mark, weaken
   asserts, or land features on known rot.
2. **Fix now** if local + stage-allowed; else **stop**, report
   path:line, route `/mol:fix` / `/mol:refactor` / supersede.
3. **Name it** in the summary (found / fixed / blocking). Silence = process failure.

Outranks "stay in scope" / "minimal diff" when those mean knowingly
leaving rot you already saw.

### Prefer

- **OOP by default.** Domain concepts are types with methods
  (`NeighborList.build`, `ForceField.energy`), not free-floating
  helpers. Module-level functions only for true free operations (pure
  math with no natural owner) or thin package re-exports.
- **Primitive, single-responsibility public APIs.** Callers compose:
  construct → configure → one concern → read result. Each public
  method does one named thing.
- **Inline until the second real use.** A helper used in exactly one
  place stays inline (or a private method on the owning type). Extract
  only at a second call site, or when a unit test must target that unit.

### Forbid

- **Factory functions as the primary constructor story.** No
  `make_foo` / `build_bar` / `create_*` wrappers around construction.
  Prefer `Foo(...)`. Explicit alternate constructors only when they
  have distinct semantics (`Foo.from_file`, `Foo.empty`) — not
  `make_foo` aliases of `__init__`.
- **God data structures.** No mega-dict / mega-struct / ambient
  "context" blob every layer reaches into. Pass the few fields a call
  needs, or a narrow typed view. Split types that accumulate more
  than one coherent responsibility.
- **All-in-one façade APIs.** No public `run_everything` /
  `compute_all` / `pipeline` that hides multi-step work. Composition
  is the **caller's** job (scripts and docs examples).
  The library exposes primitives only.
- **A global precision singleton.** Every module takes `dtype: torch.dtype`
  from its caller (a spec's `ftype`, a training config, a test constant);
  there is no `molix.config`, no `set_precision`, no `dtype=None` meaning
  "read a global" (operator ruling 2026-10-17).
- **Counting graphs off an index.** The `graphs` namespace is part of every
  batch — collate, the MD driver and the deploy adapter all produce it — and
  the graph count is `frame["graphs"].batch_size[0]`; `num_graphs` /
  `dim_size` are required arguments, never `index.max().item() + 1`.
- **"site" vocabulary and schema versions.** The per-atom energy is the atom
  energy (`atoms.energy`; `atom_energy` in the deploy convention). Deployment
  metadata and manifests carry no schema version: a reader takes the fields
  it knows and ignores the rest. Before 1.0 nothing is versioned, migrated or
  shimmed.
- **`getattr(obj, name, default)` / `hasattr` / `__getattr__` on in-repo
  objects.** `isinstance` and explicit typed attributes. The only place a
  probing read is allowed is an external-format boundary (an upstream pickled
  module, a `.nequip.zip` manifest).

### Shape check (before adding a public symbol)

1. Natural owning type? → method on that type, not a free function.
2. More than one user-visible step? → split into primitives.
3. Only one in-tree call site? → do not extract.
4. Tempted to hang another field on a "context" bag? → new parameter
   or smaller type instead.

## Iron law — everything compiles, no graph breaks

**Every hot path in molnex must run under `torch.compile` with zero graph
breaks** (`torch._dynamo.explain(...).graph_break_count == 0`, i.e.
`fullgraph=True`-clean): encoders, potentials, the energy/force/virial
kernels, neighbour-list update, integrators. Where a region truly cannot
compile (a third-party op without a compile-safe registration), the
uncompilable part is isolated behind the narrowest seam and **the compiled
region is made as large as possible**; the break is named in the module
docstring and in `.claude/notes/notes.md` topic `compile-no-graph-breaks`
with the reason and the owner. Known break sources that are forbidden on a
hot path: `.item()` / `int(tensor)` host syncs, data-dependent shapes
(boolean-mask indexing, `nonzero`, per-call `arange` of a tensor-derived
length), Python branches on tensor values, per-call `.to(device)` of freshly
built CPU tensors, pydantic / config attribute reads, dict-of-tensor keys
built per call. Dynamic sizes are handled by fixed capacity + mask (the
`NeighborList` pattern), never by data-dependent shapes. **Static shapes are
the MD default** (2026-09-11, spec `derivation-head-02-static-shapes`): the
driver hands the derivative op the list's full capacity buffer every step,
dead rows are `(0, 0)` self-loops at `molix.schema.dead_pair_shift(cutoff)`
(shared by `NeighborList` and
`MoleculePadder(max_atoms=, max_pairs=, …, max_graphs=, cutoff=)`), ghost atoms are killed by multiplying `atoms.mask` into
every per-atom energy before the graph sum (never a slice), and
`Compiler(cuda_graphs=True)` is the MD compiler (GH200: 1.9 ms/step vs 21 ms
eager at 256 atoms). **Training batches are capacity-first** (2026-09-14):
the padder owns the static shape — `MoleculePadder.from_counts(counts,
atoms=2**k, cutoff=)` sizes every cap from the dataset density and never
below the largest molecule, pads the graph count too (`max_graphs`, dead
slots + `graphs.mask`, ghosts in the sink slot) — and the loader packs under
`padder.budgets()` (`DataModule(batch_counts=, val_batch_counts=)`), so the
molecule count per batch floats and no batch can exceed a cap. Never fix the
molecule count and pad to `B × per-molecule max` (OMol25 4m: 17 M proper
rows, 10 % filled), never size a cap from a quantile, never leave the graph
count unpadded (each new `B` is a recompile). A compile test
(explain → 0 breaks) accompanies every new hot-path module.

## Iron law — no training before verified optimization

**Starting a training run is forbidden until the exact network, data-task
path, batching path, and target hardware have been thoroughly validated and
optimized.** A speculative full run is not a substitute for this gate.

Binding preflight and sign-off record:
`.claude/notes/production-training-checklist.md`.

Before any training submission, all of the following evidence must exist for
the exact configuration being submitted:

1. Dataset coordinates, versions, provenance, units, target schemas, grouping,
   and molecule-level splits have been validated.
2. Reference and optimized/packed execution agree on forward outputs, every
   active loss, gradients, and at least one optimizer update within declared
   tolerances.
3. Every active task/head passes a bounded tiny-set overfit test, and finite
   values, physical invariants, gradient norms, clipping, and outliers have
   been inspected.
4. The input path uses real packed molecular batches; avoidable per-molecule
   serial execution has been profiled and removed.
5. Representative molecular-size buckets have been calibrated on the target
   accelerator for batch size, HBM headroom, step time, throughput, and
   stability. Model dimensions and calibration candidates use powers of two.
6. A bounded smoke run demonstrates loss movement, validation reporting,
   checkpoint/resume, and failure recovery.
7. The evidence is written under one timestamped run directory.

If any item is missing or stale, only explicitly bounded validation,
profiling, or calibration jobs may run. Production launchers must fail closed
when the calibration evidence or its exact configuration fingerprint is
absent; they must never silently downgrade this rule to a warning.

**Not gates** (operator ruling, 2026-09-16): a **molexp** experiment/run record
is optional — use it where it helps, but its absence never blocks a run — and a
committed or clean git tree is never required. The gate is evidence that the
configuration works, not bookkeeping about where the evidence is filed or
whether the tree is committed.

## Project Overview

**MolNex** (v0.1.0) is a dict-first molecular ML framework for unified modeling of molecular potentials and properties with physics-aware ML. It is composed of four packages:

| Package | Role | Key Patterns |
|---------|------|-------------|
| **molix** | Training infrastructure | Trainer, TrainState (dict), Step protocol, Hook lifecycle |
| **molrep** | Representation learning | Generic blocks only: embeddings (geometry, radial, cutoff, spherical harmonics, MLPs), `interaction.product`, `molrep.cueq`, representation heads; equivariance via cuEquivariance |
| **molpot** | Potential functions | BasePotential (nn.Module + ABC), Potentials (Class-I container), PotentialComposer; derivatives via `molix.autograd.Derivative` |
| **molzoo** | Pre-built encoders and named models | Model families (MACE, Allegro, PiNet2: spec → encoder → potential, each product a `molix.autograd.Potential`) and the learnable Class-I force field **Rondo**; physics heads stay in molpot |

One-way dependency: `molix` ← `molrep` ← `molzoo` / `molpot` (molpot must not import molzoo).
Prefer explicit `nn.Linear(in, out)` over `LazyLinear` on any compile / export / functorch path.

Source ↔ unit-test path mirror:

src/<pkg>/<area>/<module>.py  →  tests/test_<pkg>/test_<area>/test_<module>.py

Gate for the model spine: `python scripts/check_test_mirror.py --strict-spine`.

Model package layout — every molzoo model has MACE's shape: a torch-free
`spec.py` (pydantic, `extra="forbid"`, every default lives here), an
`encoder.py` body exposing primitives (`ElementTable` mixin from
`molzoo/encoder.py` for the element-table precondition), a `potential.py`
product that **subclasses** the body (flat checkpoint keys) and

the one method a model writes; it reads its columns straight off the frame,

kwarg). Products take the typed spec object: `MaceMatpes(MACEMatpesSpec(...),
wrt=(), energy_dtype=torch.float64, input_dtype=None)`,
`AllegroPotential(AllegroSpec(...), wrt=())`, `PiNetPotential(PiNetSpec(),
wrt=())`. Official loading: `MaceMatpes.load(path, *, config=None, wrt=(), ...)`
→ `MaceArchive.read` → typed `MaceOfficialConfig` →
`MACEMatpesSpec.from_official(cfg)` → `CheckpointRemap(matpes_keys,
skip=MACE_SKIP)`; `AllegroPotential.load(path, *, wrt=(), tp_method=None)` over
`NequipPackage.read(path) -> (state, AllegroSpec)`. `molzoo/__init__.py` is a
docstring: import a family from its subpackage, eagerly (`from molzoo.mace
import MaceMatpes`), no lazy tables. **A block that serves one model lives in
that model's package** (`layers.py`; MACE also `heads.py`, `coupling.py`);
only generic components and operators (MLPs, radial bases, cutoffs, spherical
harmonics, edge geometry, scatter, `interaction.product`, `molrep.equivariance`)
live in molrep (operator ruling 2026-10-15; MACE blocks moved 2026-10-16).
Equivariant operations use cuEquivariance's descriptors (`molrep.eq`) on
molnex's own kernels (`molrep.equivariance`).

src/molrep/embedding/geometry.py   # edge_vectors / edge_lengths (the one owner)

## Architecture

### Two-tier data contract (raw sample vs collated batch)

The data path speaks **two** shapes. They are intentionally different — get
this wrong and `KeyError(('pairs','pair_index'))` is the first thing you see.

| Stage | Container | Example access |
|---|---|---|
| MolHub-side sample production / preprocessing I/O, `FrameDataset[i]` | **flat `dict`** | `sample["Z"]`, `sample["pair_index"]`, `sample["targets"]["U0"]` |
| Post-`collate_molecules` (what encoders / losses receive) | **nested `TensorDict`** (plain, no subclass) | `batch["atoms", "Z"]`, `batch["pairs", "pair_index"]`, `batch["graphs", "energy"]` |

The single conversion point is `molix.data.collate.collate_molecules`
(invoked by `DataModule._CollateFn`). Stats / diagnostics operating on
individual cached samples use **flat** keys; model / loss / metric code
operating on batches uses **nested tuple-keys**.

#### Post-collate batch schema

```
TensorDict (batch_size=[])
├── "atoms": TensorDict (batch_size=[N])
│   ├── Z: atomic numbers (N,)
│   ├── pos: positions (N, 3)
│   ├── mass: atomic masses (N,) amu  [MD]
│   ├── vel: velocities (N, 3) Å/fs   [MD]
│   └── batch: graph membership (N,)
├── "pairs": TensorDict (batch_size=[E])
│   ├── pair_index: source-target pairs (E, 2)   # [:,0]=source, [:,1]=target
│   ├── pair_diff: edge vectors (E, 3)            # pos[target] - pos[source]
│   ├── pair_dist: edge distances (E,)
│   └── shifts: periodic remainders (E, 3)  [optional]  # pos[t]-pos[s]+shift = min-image vector, Å
└── "graphs": TensorDict (batch_size=[B])  [optional]
    ├── num_atoms: (B,)
    ├── cell: cell vectors (B, 3, 3)  [optional]  # Å; rows = lattice vectors, from frame.box
    └── <targets>
```

### Row counts: an attribute, a declaration, and a request

Three spellings, deliberately different, because they cost different things:

| Spelling | What | Cost |
|---|---|---|
| `frame["atoms"].n_rows` | molpy `Block` **attribute** — this one block's length | free |
| `MyDataset.counted_tables = {"atoms": "_n_atoms"}` | **declaration** — this container already holds the per-row vector in that attribute | a read |
| `MyDataset.count_rows(table)` | **verb** — the container has to measure, and may cache what it measured | a scan, once |
| `BaseDataset.nrows_of(source, table)` | the one **request** every batch budget goes through | whichever of the three applies |

`nrows_of` tries them cheapest-first and falls back to materialising every
sample. That fallback is correct and is the slowest thing in a data path: on a
four-million-row LMDB it is a quarter of an hour (measured 140-230 us/row), so
a container that can do better must say so.

There is deliberately **no** `dataset.nrows(table)`. A `Block.n_rows` attribute
returning a scalar and a dataset method returning a vector would read the same
at the call site and mean different things; the verb and the declaration keep
them apart.

`("pairs", "shifts")` is written by the MD bind path (`molix.md.NeighborList.build`);
no molzoo model reads it — they read the imaged `pairs.pair_diff` (value) with
the gradient through `atoms.pos` (`molrep.embedding.geometry.edge_vectors`);
no potential takes a `shifts=` argument. `("graphs", "cell")` is read by
`molpot.composition.sonata` (stress). On the MD bind path the `pairs`
namespace has `batch_size=[capacity]` with live pairs in `[0, num_pairs)`
and dead padding beyond — the list owns `pairs` once bound.

Access: `batch["atoms", "Z"]`, `batch["pairs", "pair_dist"]`. Encoders
mutate the batch in place, writing `node_features` under `atoms` and
`edge_features` under `pairs` — the ML feature column on the chemistry
namespace, dual to `node_features` on `atoms` — no subclass swap.

### On-disk format — molnex has none

molnex **reads** datasets; it does not define a file format. Acquiring the
data — download, parse, preprocess, cache — is MolHub's, and so is whatever it
is stored in. A dataset reaches molnex as an indexable space of molpy `Frame`s
behind `molix.data.BaseDataset`, and that protocol is the whole contract.

molnex did carry its own format, `molix.block/1` (`FrameStoreWriter` /
`FrameStoreReader` / `FrameStoreDataset` — a directory of raw little-endian
column files with a crc32 commit log and per-column sha256). It was **deleted
on 2026-09-17** (spec `data-layer-01-consolidation`) because it had no
producer, no consumer and no instance on disk: the only `FrameStoreWriter` call
outside its own tests was a benchmark, the Class-I production path reads
MolHub's LMDB (measured call stack `molhub/io/lmdb.py:94`), and molhub's import
of it had been broken since 2026-09-08 without anyone noticing. About 5 500
lines of code and tests went with it, together with a second collate route in
`DataModule` that was probed on every dataloader build and could never fire.
**Do not reintroduce a molnex file format**: a faster on-disk shape belongs to
MolHub, and molnex grows at most an alternate constructor on `FrameDataset` to
read it.

A dataset carries **no neighbour graph** — the cutoff graph is a function of
positions and a radius, so it is built by `molix.neighbor.NeighborList`, never
stored. A dataset that can answer a table length without materialising a
sample (a count sidecar, `n_<table>` / `<family>_n`) lets the sampler budget a
whole epoch with zero `__getitem__` calls; it declares them in
`BaseDataset.counted_tables`, and every batch budget asks for them through
`BaseDataset.nrows_of(source, table)`.

### Two vocabularies, one seam: `pairs` (chemistry) vs `edge` (ML)

The cutoff neighbour list is a **pair list** in every chemistry-layer surface
and a **graph edge set** inside the models, and each name is right where it
sits (decision 2026-09-15):

| layer | spelling | where |
|---|---|---|
| chemistry / data | `pairs` namespace, `pair_index` / `pair_diff` / `pair_dist`, `max_pairs`, `num_pairs`, `dead_pair_shift` | `TensorFrame` and the batch schema, collate, `MoleculePadder`, the samplers, `molix.data`, `molix.md`, `molix.deploy`, all of `molpot`, `interface/` |
| ML / graph net | `edge_index` / `edge_diff` / `edge_attrs` / `edge_feats` as **parameter and local names** | `molrep` blocks, `molzoo` encoders, and the kwargs dicts they pass among themselves |

The seam is explicit and lives in the encoder's first line —
`edge_index = batch["pairs", "pair_index"]`, *the chemistry pair list, read as
graph edges*. A call site follows its **callee**: building a batch takes the
chemistry names even inside an ML test; calling a molrep block takes `edge_*`
even from molpot. Feature columns keep the ML word on the chemistry
namespace — `atoms.node_features` and `pairs.edge_features` are duals.

Why not one word: `edges` read as *bonds*, and a cutoff pair list is not a
bond list — on OMol25 4m at a 10 Å list there are 68.7 pairs per atom against
1.76 angles per atom, a factor of N apart.

### Edge Convention (MUST follow everywhere)

```
pair_index[:, 0]  — source atom  (the "centre" in Allegro; the "sender" in MACE ConvTP)
pair_index[:, 1]  — target atom  (the "neighbour" in Allegro; the "receiver" in MACE ConvTP)
pair_diff         — pos[target] - pos[source]   (displacement vector, source → target)
pair_dist         — ‖pair_diff‖
```

`NeighborList` defaults to **full bidirectional** edges (`symmetry=True`, `E = 2 × n_pairs`).
Pass `symmetry=False` to get only the upper-triangle half-pairs (`E = n_pairs`) when you explicitly
want to exploit Newton's-3rd-law symmetry.  The two modes produce different `task_id`s so their
preprocessed caches are kept separate.

`pair_index` is `(E, 2)` **everywhere** — including every MACE-family block
(`DensityInteraction`, `ResidualInteraction`, `ZBLRepulsion`, both model cores).
Upstream MACE's `(2, E)` layout is transposed away at the checkpoint-port
boundary and never crosses a module seam; unpack as `source, target`
(never `sender, receiver`). `(2, N)` is reserved for `bond_index`.

**Why pair_diff = pos[target] − pos[source]?**  This makes the displacement vector point in the
same direction as the edge (source → target), which is the convention expected by `SphericalHarmonics`
and all `cuEquivariance`-based tensor products in this repo.  The C++ `getNeighborPairs` kernel
returns `pos[rows] − pos[cols]` (opposite sign); `NeighborList.execute` negates it.

### `pair_index` (cutoff graph) vs `bond_index` (covalent topology)

Two **different** connectivity objects, with **deliberately different shapes**
so one can never be silently used as the other:

| field | shape | meaning | offset axis |
|---|---|---|---|
| `pair_index` | `(E, 2)` | geometric neighbour graph `G(r_c)` — recomputed from positions each step, bidirectional, includes through-space contacts | rows |
| `bond_index` | `(2, N)` COO | fixed covalent topology (from molpy `atomi`/`atomj`), paired with `bond_types`; consumed by `BondHarmonic` and other bonded terms | columns |

A within-cutoff neighbour is **not** a chemical bond. `BondHarmonic` rejects a
`(E, 2)` tensor passed as `bond_index` (raises, rather than computing a wrong
energy) — the transpose is a type-level anti-alias guard. The collated batch
exposes bonds under a `"bonds"` namespace (`batch["bonds", "bond_index"]`,
`batch["bonds", "bond_types"]`, `batch_size=[]`).

### torch_geometric collate/Batch parity

molnex's batch is a plain nested `TensorDict`, not a PyG `Data`/`Batch`. The
collate intentionally implements only the lazy subset of PyG's batching:

| PyG feature | molnex | why |
|---|---|---|
| `__inc__` / `__cat_dim__` (per-key offset on batching) | **implemented** as the declarative `INDEX_KEYS` registry + `rebase()` in `collate.py` | the one piece worth having — also fixes the latent un-offset `bond_index` bug |
| `follow_batch` (per-attribute batch vectors) | **skip** | no consumer |
| `ptr` (cumsum boundaries) | **skip** — derive on demand from `graphs.num_atoms` / `atom_ptr` | redundant to materialise |
| `to_data_list()` / unbatch | **skip** | persistence is MolHub's, not molnex's |
| `exclude_keys` | **skip** | no consumer |
| arbitrary `HeteroData` node/edge types | **skip** | fixed `atoms`/`pairs`/`graphs`/`bonds` namespaces are the contract |

The packed-mmap collate fast path (`collate_packed`) is a deliberate
divergence from PyG's per-sample Python `Collater` — faster and HPC-fs
friendly for fixed-schema molecular data.

### State namespace contract

`TrainState` (`src/molix/core/state.py`) is a dict with a **fixed
top-level layout**. Every metric / scalar produced during training lives
inside one of four **namespace sub-dicts**, never at the top level with
a slash-prefix key.

| top-level key         | owner                    | kind        |
|-----------------------|--------------------------|-------------|
| `epoch`               | `Trainer`                | counter     |
| `global_step`         | `Trainer`                | counter     |
| `stage`               | `Trainer` (`Stage` enum) | counter     |
| `steps_since_last_eval` | `Trainer`              | counter     |
| `best_metric`         | `CheckpointHook`         | scalar      |
| `train`               | train-phase hooks        | **dict**    |
| `eval`                | eval-phase hooks         | **dict**    |
| `performance`         | throughput/timing hooks  | **dict**    |
| `gpu`                 | GPU telemetry hooks      | **dict**    |

**Writes — always nest.** Hooks must write into the namespace
sub-dict, never into the flat root with a slash:

```python
# ✅ correct
state["train"]["loss"] = loss.item()
state["eval"]["MAE"] = mae
state["performance"]["step_per_second"] = rate
state["gpu"]["peak_gib"] = peak

# ❌ rejected at __setitem__ — raises ValueError
state["train/loss"] = loss.item()
state[("train", "loss")] = loss.item()
```

This prevents two hooks from silently sharing a flat namespace and
colliding on keys (which is exactly how the train/MAE-exploded-to-203
bug happened: eval path wrote into an accumulator shared with the
train path).

**Reads — three equivalent forms, no helper required.**
:class:`TrainState` walks its nesting on read. All three of these
return the same value (or ``None`` / a default if any segment misses):

```python
state["eval"]["MAE"]            # nested dict access
state["eval/MAE"]               # slash-string path
state[("eval", "MAE")]          # tuple path

state.get("eval/MAE")           # all four: same fallback semantics
state.get(("eval", "MAE"))
state.get("epoch")              # plain top-level key still works
"eval/MAE" in state             # walk-aware __contains__
```

For arbitrary ``Mapping`` instances (e.g. plain ``dict`` snapshots),
:func:`molix.core.state.resolve` accepts the same shapes:

```python
from molix.core.state import resolve, display

resolve(state, ("train", "loss"))     # tuple path
resolve(state, "train/loss")          # slash string
resolve(state, "epoch", default=0)    # flat key with default
display(("train", "loss"))            # → "train/loss"  (for column headers)
```

The slash-string form is fine for *reads* — Log column headers,
TensorBoard tags, and external scripts addressing scalars all benefit
from a single string identifier. Only the *write* side stays
nested-only, which is what actually prevents namespace collisions.

**Phase-ownership rules for hooks.**

1. `on_train_batch_end`, `on_after_backward` — may write to
   `state["train"]`, `state["performance"]`, `state["gpu"]`.
2. `on_eval_batch_end`, `on_eval_step_complete` — may write to
   `state["eval"]`.
3. `on_epoch_start` / `on_epoch_end` — may write anywhere they own
   by phase, but should **prefer the per-phase callbacks** so readers
   have deterministic ordering.
4. **Hooks must not share mutable buffers between train and val.**
   If a hook needs the same metric on both sides (e.g. `MetricsHook`
   with `MAE`), it must hold two distinct instances — typically via
   `copy.deepcopy` in `__init__` — so a `.reset()` / `.update()` on
   the val side is invisible to the train side.

**Trainer guarantees for eval-phase hooks.**
`_run_eval_phase` fires `on_eval_step_complete` at the end of **every**
eval phase (both step-based `eval_every_n_steps` and epoch-end),
before the LR scheduler reads `best_metric_name`. Eval-publishing
hooks (`MetricsHook`, `TensorBoardHook`) should write their
`state["eval"]` scalars from `on_eval_step_complete`, not
`on_epoch_end`, to be available for the scheduler's read.

### Key Design Patterns

- **Encoder body + product**: an encoder's `forward(td)` takes the post-collate batch, writes per-layer features `(N, layers, features)` under `atoms.node_features` (`pairs.edge_features` for Allegro) and exposes its primitives as methods; the named products (`MaceMatpes`, `AllegroPotential`, `PiNetPotential`, …) subclass the body and `molix.autograd.Potential` and own only `energy(frame)` + `forward`; reusable physics heads stay in molpot. Element-table validation is `molzoo.encoder.ElementTable`, spent once on the first eager call and folded out under tracing.
- **Pydantic specs**: molzoo model specs are torch-free `BaseModel`s with `ConfigDict(extra="forbid")` — typed fields and validators, no `getattr(spec, …, default)` duck typing; official-archive configs (`MaceOfficialConfig`, `NequipConfig`) use `extra="ignore"` and declare only the fields that are read; molpot head specs that carry tensors use `ConfigDict(arbitrary_types_allowed=True, frozen=True)`
- **Equivariance**: group theory and descriptors are cuEquivariance's ported frontend `molrep.eq` / `molrep.eq.torch` (`import molrep.eq as meq`); every contraction runs on molnex's own operators in `molrep.equivariance` — `ChannelWiseTensorProduct`, `SymmetricContraction`, `SphericalHarmonics`, Allegro's `Contracter` and `WeightedChannels`, and `Linear` (one GEMM per irrep block over cue's linear descriptor, same flat `weight`) — on CUDA through `libmolnex_equivariance` (`csrc/equivariance`, namespace `molnex_equivariance`: deterministic, fused first and second adjoints, Meta kernels, loaded through `MOLNEX_OP_LIBRARY_PATH`) and on CPU through `molrep.equivariance.reference`, the same term table in plain PyTorch (tests and correctness only). The device of the tensor picks the path; there is no `method=` switch, no `use_fallback`, and no cuEquivariance kernel on any path (replacement completed 2026-10-26, notes topic `native-equivariance-default`; the earlier `cue-kernels-only` ruling is superseded). Precision is fixed at construction (`dtype=`), never cast. Edge convolutions are always indexed (conv fusion): global `indices_out` with `size_out=N`, the CSR edge schedule built once per batch by the encoder. Never `conv_tp(x[source], …)` + Python `scatter_sum`, which materialises an `(E, target.dim)` message (`.claude/notes/notes.md` topic `cueq-conv-fusion`).
- **Force derivation (one op)**: every batch-level derivative is `molix.autograd.Derivative(energy, *, of="graphs.energy", wrt=(), outputs=None)` — `energy(frame) -> frame` writes `of`; `wrt` names TensorFrame keys (`"atoms.pos" → atoms.forces` scale −1, `"graphs.strain" → graphs.virial` (1,3,3) symmetrised, any other column → `<ns>.<name>_grad`). The op makes a leaf for every variable unless the column already is a live leaf (then it is differentiated as is and left in the frame — the caller's), rebuilds live edge geometry from it, does the one `torch.autograd.grad`, puts the caller's buffers back, detaches `of` iff grad is off; `Derivative.mark_leaves(frame)` is the eager prologue that marks the columns so a force-supervised training step traces as one graph on stock torch (the default steps run it in `forward_loss` before the traced body). Every potential exposes `energy(frame)` and takes `wrt=()` at construction; `forward` is the op built in `__init__` (`MaceMatpes(..., wrt=("atoms.pos",))` ≡ `Derivative(MaceMatpes(...).energy, wrt=("atoms.pos",))`; base class `molix.autograd.Potential`, never `Derivative(<potential object>)`). `MD` composes `Derivative(pots.energy, wrt=("atoms.pos"[, "graphs.strain"]))` once per run; compile with `Compiler(...)(op)` after one eager forward — no `compile_core`, no `compute_forces`, no `calc_forces` family. There is no other force module: `Sonata`, `PotentialComposer`, `Rondo` and the model zoo are `Potential`s on this op; `HessianDerivation` owns its own leaf and calls `torch.autograd` directly. Do not hand-roll a second force or virial path anywhere (decision 2026-09-11, spec `derivation-head-04-molix-derivative`).
- **Composed potentials**: `PotentialComposer` and `Sonata` are `molix.autograd.Potential`s — `energy` runs heads → terms → aggregation on the frame, `forward` is the `Derivative`
- **Hook protocol**: Lifecycle callbacks (`on_train_start`, `on_epoch_end`, etc.) via `Hook` protocol
- **Step protocol**: `DefaultTrainStep` / `DefaultEvalStep` wrap forward → loss → backward → optimizer; `forward_loss(trainer, state, batch)` (model forward + loss) is the one traced function and `Trainer.compile(step=True)` compiles it in place (`step=False` compiles the model only; a step whose traced body host-syncs declares `untraceable` and is refused by name). `MultiTaskTrainStep` reads the task label in the eager prologue, outside that body. `smoke` runs the same `forward_loss`. Spec `derivation-head-03-step-compile`.

### TensorDict Contract

The post-collate batch is a `tensordict.TensorDict`. `molix.frame.TensorFrame`
(`mn.TensorFrame`, a `TypedTensorDict`) is the **typed view** of that batch: its
declared fields are exactly the namespaces in the table above — `atoms`
required, `pairs` / `graphs` / `bonds` / `angles` / `propers` / `impropers`
`NotRequired`. It adds no storage and no behaviour;
`TensorFrame.from_tensordict(batch)` is a zero-copy wrap (every leaf keeps its
storage), and it traces to the same dynamo graph as the plain batch. Its name
differs from molpy's `Frame` so a reader always knows which side of
`collate_molecules` they are on.

The `AtomData / EdgeData / GraphData / GraphBatch` subclasses that existed
before 2026-05-18 stay removed — they carried behaviour and per-class storage,
which is the thing that is forbidden, not the type declaration.

**Rules for new code:**
- Build batches as plain `TensorDict(..., batch_size=[N])`; wrap in
  `TensorFrame` where a typed read is wanted. Never write a batch container
  that owns storage or methods.
- Encoders: prefer inheriting `TensorDictModuleBase` for `in_keys`/`out_keys`
  validation. Plain `nn.Module` is accepted as long as `forward(td: TensorDict)
  -> TensorDict` is respected.
- Do not introduce `@tensorclass` dataclass wrappers for batch containers.

### Adding New Components

**New model family** (molzoo): a subpackage `molzoo/<family>/` in MACE's shape. `spec.py`: torch-free pydantic spec (`extra="forbid"`, every default here). `encoder.py`: the body, `class <Family>Encoder(ElementTable, nn.Module)` (`molzoo.encoder.ElementTable`), `__init__(spec)`, primitives as methods, `forward(td: TensorDict) -> TensorDict` reading `td["atoms", "Z"]` / `td["pairs", ...]` and writing per-layer features `(N, layers, features)` under `atoms.node_features`. `layers.py`: the blocks only this family uses (generic ones come from `molrep`). `potential.py`: `class <Family>Potential(Potential, <Family>Encoder)` taking `(spec, *, wrt=())`, implementing `energy(frame)` only and ending `__init__` with `self._derivative = Derivative(self.energy, wrt=wrt)`; official weights, if any, through a `checkpoint.py` key table + an `OfficialArchive` reader in `utils.py` behind `.load(path, *, wrt=(), ...)` and `CheckpointRemap(table, skip=...)`. Export eagerly from `molzoo/<family>/__init__.py`, never from `molzoo/__init__.py`. Add the paper reference and the spec under `src/molzoo/specs/` (mirrored to `docs/molzoo/specs/`).

**New potential** (molpot): one class per molrs style under `molpot.potentials` (`bond.py`, `angle.py`, `dihedral.py`, `improper.py`, `pair.py`), registered with `@register`, built from the force field by `from_style` and reached through `Potentials.from_forcefield(ff)`; a bonded style implements `term_energy(x, **params)`, a pair style prices `pairs` under the field's `special_bonds`. Forces come from `molix.autograd.Derivative`. `BasePotential` (keyword-only tensor kernels: `forward(*, pos, <term>_index, <term>_types, term_batch, num_graphs, tables)` reducing per graph) is the fixed tabulated path (MD / export / OPLS-AA).

**New embedding/interaction** (molrep): only when at least two families use it — a block that serves one model lives in that model's `layers.py`. Pure `nn.Module`; build cue ops through `molrep.cueq`.

## Scientific Correctness Requirements

Every implementation of a physical model, potential, or operator MUST:
1. Reference the original publication (arXiv/DOI) in the module docstring
2. Match the equations in the paper — document any deviations with rationale
3. Include numerical validation tests against reference implementations or published values
4. Preserve physical symmetries (energy conservation, rotational/translational invariance, permutation equivariance)

## PyTorch Version Policy

This project tracks **latest stable PyTorch** (currently >=2.10). Use modern PyTorch APIs:
- `torch.compile` for performance-critical paths
- `torch.export` for model serialization
- `torch.nn.functional` over deprecated module alternatives
- Native `torch.nested` for variable-length sequences where appropriate

The flow is `scaffold → fill → implement → audit`; reverse workflows ("write code first, retrofit the spec") are the failure mode this whole apparatus exists to prevent. See "Spec-First Principle" in `.claude/skills/molzoo-spec/SKILL.md` for the full rule.

There is **no** `_experiments.csv` and **no** `_walkthrough.md`. Run logs are §7.4 of `<encoder>.md` (markdown table, append-only). Audit verdicts from `molzoo-auditor` are **printed to the developer at chat time**, not tracked as files; on 📝/🆚 the agent patches `<encoder>.md` directly and that diff is the persistent trace.

One skill + one agent. Both repo-local under `.claude/skills/` and `.claude/agents/` — do not promote to `~/.claude/` without a second repo adopting the same pattern.

|---------|---------|--------|
| Introduce a new encoder | `/molzoo-spec <encoder> --paper <arxiv_url> [--ref <org>/<repo>@<sha>]` | **create mode** (auto-detected when spec is missing): copies the 10-section template to both spec copies; header + §1 + §9 only; status `draft`. Code authoring forbidden. |

Bumps status `draft` → `partial` once §2/§3/§5 are filled; required before `<encoder>.py` is written. |
| After a bench / training run | `/molzoo-spec <encoder> --log <k=v ...>` | appends one row to §7.4; on MAE regression > 10 % or dirty tree, warns + suggests `molzoo-auditor`. |

| Verify code vs spec vs paper | `molzoo-auditor` agent | **prints** ≥ 1 verdict report (✅ ℹ️ ⚠️ 📝 🆚) to the developer; ⚠️ (code-drift) recommends a code change without editing spec; 📝/🆚 patch `<encoder>.md` directly; may backfill the §7.4 `note` cell. |

**Closed-loop contract.** Every operation either updates `<encoder>.md`, prints a verdict, or explicitly delegates — no operation closes silently:

1. `/molzoo-spec <encoder> --paper <url>` triggers create mode only when the spec file is absent; status starts `draft`.
2. `/molzoo-spec <encoder>` triggers update mode when the spec exists; it MUST be run before any code is written and bumps status to `partial`. Code authored against status `draft` is a process violation, not just drift (see §10.3 in the spec template).
3. `/molzoo-spec <encoder> --log <k=v ...>` is append-only on §7.4; it MUST check the previous row and warn (not auto-invoke) on anomalies.
4. Questions about spec content are answered inline under the skill's §"Lookup Behavior" hard rule — `Read` the spec, quote verbatim, refuse on a miss, refuse outright on a `draft`-status spec and point at update mode.
5. `molzoo-auditor` MUST print ≥ 1 verdict per invocation (even `✅ confirmed, no drift`), citing the triggering `run_id` or question + paper section + spec row + code file:line. ⚠️ (code-drift) is print-only; 📝/🆚 produce file diffs in `<encoder>.md`. The auditor never edits code — code changes are always the user's call.

The 10-section structure of `<encoder>.md` is **immutable** — adding / removing / renaming a section is a §10.2 breaking change. Invariants are enforced inside the skill, not via `settings.json` hooks, for now.

## Learnable classical FF — placement (binding)

See `.claude/notes/learnable-classical-ff.md`. Short form:

0. **The named product is `Rondo`** (`src/molzoo/rondo/`, spec
   `src/molzoo/specs/rondo.md`), shaped like every other molzoo model:
   `Rondo(forcefield, spec, wrt=("atoms.pos",))`, `forward = Derivative(energy, wrt)`.
   The force field **is** the Hamiltonian — a molpy `ForceField` (molrs IR,
   LAMMPS `K` without ½, degrees) declares styles / cutoff / mixing / Coulomb
   constant / special bonds once; `Potentials.from_forcefield(ff)` is the one
   factory. Rondo adds `ChemEncoder` (ByteFF channels), `Hybridization` and one
   head per open parameter (`molpot.heads.classical`); three primitives —
   `tables(frame)`, `energy(frame, tables=None, styles=None)`, `partial_hessian(frame, tables=None)`
   — and **no training-stage arguments** (no `outputs=` / `trainable=` /
   `energy_terms=` / `param_groups`; user ruling 2026-10-11). Which loss trains
   which parameters is the training step's: `molix.core.steps.JointObjective(trainable=)`
   detaches the other tables between `tables` and `energy`; the optimizer is
   `Adam(model.parameters())`. Training is ByteFF's joint multi-source step
   (`JointTrainStep` + `JointDataModule`). `energy` writes `graphs.energy` and
   every table column (`bonds.k`, `bonds.k_ref`, …, `atoms.charge`); `forward`
   adds `atoms.forces_pred`. Placing predictions beside the DFT labels is the
   joint step's job (`molix.frame.beside_labels`), not the model's.
   Required input columns (MolHub writes them for THEMol): `atoms.formal_charge`,
   `ring_connectivity`, `min_ring_size`, `gaff2_sigma`, `gaff2_epsilon`;
   `bonds.bond_type`, `in_ring`; `impropers` as three cyclic rows per centre.
1. **Style potentials are molrs-verbatim** (`molpot.potentials`, one class per
   molrs style, registered with `@register`): what is fixed about the form
   (cutoff, mixing, special bonds, Coulomb constant) comes from the force field
   at `from_style`; predicted parameters are call arguments
   (`potential(frame, **params)`). Bonded potentials expose
   `term_energy(x (M, w, 3), **params) -> (M,)` — the same call serves the energy
   and the per-term partial Hessian. Pair potentials weight each pair by the
   field's `special_bonds` entry of `pairs.relation` (0 none, 1/2/3 =
   1-2/1-3/1-4, from the loader task `molix.data.PairRelation`), so the model
   does no host work per batch. The fixed
   (tabulated) path — molnex `ForceField` (a `molpy.ForceField` subclass),
   `OPLSAAForceField`, `to_potentials()`, `Potentials` — stays for MD / export /
   OPLS-AA and is not what a learned field uses. IO is `molpy.io` after
   `realize(system)`; graph → SMARTS is `molpy.io.write_smarts`.
2. **Generalize without `Foo(method=…)`** — single-responsibility types only; no multi-backend method switches on new APIs.
3. **Non-diff sinks to molpy/molrs** — *enumeration*, SMARTS, classical non-torch E/F, FF tables under molpy (≥0.13, with `k_B` / `openmm` preset). Imports: `molpy` only (never bare `molrs`).
4. **Batch topology lives in molix TensorDict**, not molpy Frame. Column form under namespaces, e.g. `batch["angles"]["atomi"]` / `batch["angles", "atomj"]` / `atomk` (propers/impropers add `atoml`; improper **center = atomi**). Stack to COO only at kernel call sites if a potential still wants `[arity, N]`.
5. **Units** — `from molix.units import units` and pint `.to(...)`. Do not restate conversion floats.
6. **Composable-potential roadmap** — the S1–S8 spec ↔ molnex mapping, the shared
   `InteractionContract` / `ModelManifest` / variational-polarization designs, and the
   `composable-a0` → `a1` → `iface` → `b1` → `b2` → `a2` chains live in
   `.claude/notes/composable-potentials.md`. Open later chains with `/mol:spec` only
   after re-reading it.
